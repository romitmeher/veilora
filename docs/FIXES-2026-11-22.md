# Headless fixes — 2026-11-22

## Changes

- VPN connection supervision retries synchronous errors, asynchronous errors, and timeouts. User disconnect cancels retries and pending discovery; stale engine events cannot overwrite a replacement connection.
- Windows DNS handling preserves each active adapter's GUID, static IPv4/IPv6 server lists, and automatic DNS configuration. Failed setup attempts roll back; failed restoration retains the snapshot for a later retry. Snapshot failure prevents DNS changes.
- OpenVPN discovery rejects directories masquerading as executables. Windows installer downloads select amd64/arm64, use a unique temporary directory, limit download size/time, check Authenticode status and publisher, and verify engine discovery before reporting readiness.
- The unsafe Windows firewall implementation is disabled. The desktop option and backend explicitly reject kill-switch activation; no working kill switch is claimed.
- Mobile retains a persistent demo notice and simulated connection labels. Desktop DNS controls are labelled custom DNS rather than leak protection.
- Removed the frontend unused import and corrected the Go lint findings.

## Remaining limits

Veilora is not a dependency-free VPN executable: the external tunnel engine/driver and Windows WebView2 remain required. Installer execution, live server connectivity, driver integration, filtering, DNS leaks, and native mobile builds are unverified. Windows DNS command execution still needs isolated-machine integration tests; snapshots are in memory and do not survive a crash. macOS/Linux DNS implementations were not rewritten or integration-tested. The mobile app remains a simulation. Kill-switch support needs a replacement implementation and isolated-machine validation.
